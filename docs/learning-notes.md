## ステップ1:プロジェクトの作成

### 1-1. 使ったコマンドと、各オプションの意味

```bash
npx create-next-app@latest . --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm
```

| 部分 | 意味 |
|---|---|
| `npx create-next-app@latest` | **Next.js** の最新版で、プロジェクトの雛形を作る |
| `.` | 今いるフォルダにそのまま作る(新しいサブフォルダは作らない) |
| `--typescript` | **TypeScript** で作る |
| `--tailwind` | **Tailwind CSS** を設定済みにする |
| `--eslint` | **ESLint** を設定済みにする |
| `--app` | **App Router** を使う |
| `--src-dir` | コードを `src/` フォルダの中に置く |
| `--import-alias "@/*"` | `@/` から始まる短い書き方で `src/` 内のファイルを読み込めるようにする |
| `--use-npm` | パッケージ管理に **npm** を使う |

ポイントは、これらの選択を最初にコマンドで決めておくと、あとから設定し直す手間が省けることです。

### 1-2. 生成されたファイルの役割

| ファイル / フォルダ | 役割 |
|---|---|
| `package.json` | プロジェクトの設計図。使うライブラリと、`npm run dev` などのコマンドが書かれている |
| `package-lock.json` | 実際に入ったライブラリのバージョンの記録。手で編集しない |
| `src/app/page.tsx` | トップページ(`/`)の中身 |
| `src/app/layout.tsx` | 全ページ共通の枠(HTMLの外側) |
| `src/app/globals.css` | 全体のCSS。Tailwind CSSの読み込みもここにある |
| `tsconfig.json` | TypeScriptの設定 |
| `next.config.ts` | Next.js自体の設定 |
| `eslint.config.mjs` | コードの書き方チェックの設定 |
| `.gitignore` | Gitの管理に入れないファイルの一覧 |
| `AGENTS.md` | Next.jsが自動で作る、AIツール向けのメモ。アプリの動作には関係しない |
| `node_modules/` | 入れたライブラリの実体。大量にあるので触らない。Gitにも入れない |
| `.next/` | 実行時に自動生成される作業ファイル。触らない。Gitにも入れない |

### 1-3. `.gitignore` と秘密情報

`.gitignore` には `.env*` という行がある。これは、`.env` で始まるファイルをGitの管理対象から外す設定である。

後のステップで、Slack Incoming Webhook の URL を `.env.local` というファイルに書く。このURLを知っている人は誰でもSlackのチャンネルに投稿できるため、リポジトリに入れてはいけない。`.env*` が最初から無視される設定になっているので、達成基準の「Webhook URL がリポジトリにコミットされていない」を満たしやすい状態になっている。

### 1-4. 脆弱性の警告との付き合い方

`npm install` の最後に `5 high severity vulnerabilities` と表示された。

- `npm audit fix --force` は、バージョンを強制的に変える。プロジェクトが動かなくなる可能性があるため、内容を確認せずに実行しない。
- 警告の内容は `npm audit` で確認できる。開発時にしか使わないツールが原因のことも多い。
- 学習用のプロジェクトでは、まず動かして内容を理解することを優先する。公開するアプリでは、ここを見直す。

### 1-5. 開発サーバーで動作確認する

```bash
npm run dev
```

- **開発サーバー** が起動し、`http://localhost:3000` で画面を確認できる。
- コードを保存すると、ブラウザが自動で更新される。
- 止めるときは、ターミナルで `Ctrl + C` を押す。

Next.jsの初期画面(「To get started, edit the page.tsx file.」)が表示されれば、プロジェクトの作成は成功である。

## ステップ2:フォーム画面の作成

ここでは「見た目」だけを作り、送信処理はまだ入れていない。

### 2-1. 作ったもの

| ファイル | 内容 |
|---|---|
| `src/components/contact-form.tsx`(新規) | 3項目のフォーム本体(名前、メール、内容、送信ボタン) |
| `src/app/page.tsx` | 初期画面を削除し、カードの中にタイトル、説明文、フォームを置いた |
| `src/app/layout.tsx` | `lang="ja"` に変更し、タブのタイトルを「お問い合わせ」に変更 |
| `src/app/globals.css` | 日本語フォント(Hiragino Sans、Yu Gothic UI、Meiryo)を指定 |

### 2-2. ページと部品を分ける理由

`page.tsx` は「ページの組み立て」、`contact-form.tsx` は「フォームという部品」を担当する。部品を分けておくと、次のステップでフォームに機能を足すときに、`page.tsx` を触らずに済む。

### 2-3. Tailwind CSS の考え方

- `rounded-lg`(角を丸くする)、`px-3.5`(左右の余白)のような小さなクラス名を、HTMLの `className` に並べて見た目を作る。
- `dark:` を前に付けたクラスは、PCがダークモードのときだけ有効になる。例:`bg-white dark:bg-zinc-900`
- `focus:` を前に付けたクラスは、入力欄にカーソルが入っているときだけ有効になる。このフォームでは、緑の枠線を出している。
- 長いクラス名を3回書くのを避けるため、共通部分を `fieldClass` という変数にまとめた。見た目を変えたいときは、変数の1か所を直せばよい。

### 2-4. フォームの作りで押さえたこと

| 項目 | 内容 |
|---|---|
| `label` の `htmlFor` と、`input` の `id` | 同じ名前にして結び付ける。ラベルの文字をクリックしても入力欄が選択され、スクリーンリーダーが項目名を読み上げられる |
| `name="name"` など | 次のステップで、送信内容を項目名ごとに取り出す目印になる。入れ忘れると、値が取り出せない |
| `type="email"` | スマートフォンでメール用のキーボードが出る |
| `noValidate` | ブラウザ標準のチェックを止める。チェックとエラーメッセージは、zodで自分で決めるため |
| `event.preventDefault()` | フォームの標準動作(ページの再読み込み)を止める。今は送信処理がないための暫定対応で、ステップ3〜4で置き換える |

### 2-5. `"use client"` とは

Next.js(App Router)の部品は、初期状態では「サーバー側で組み立てる部品(サーバーコンポーネント)」になる。ボタンを押したときの処理や、エラー表示のように「ブラウザ上で動く」機能を持たせたい部品は、ファイルの先頭に `"use client"` と書いて、ブラウザ側の部品(クライアントコンポーネント)にする。

このフォームは、次のステップでエラーメッセージを画面に出すため、今のうちに `"use client"` を付けた。

### 2-6. 見た目で気を付けたこと

- **ボタンの色**:ライトモードは濃い緑に白文字、ダークモードは明るい緑に黒文字にした。明るい緑に白文字だと、文字が読みにくくなる(コントラストが不足する)ため。
- **日本語フォント**:雛形の設定は日本語フォントを持たない `Arial` だった。日本語を含むフォントの並びに変更した。
- **開発用の「N」アイコン**:画面の左下に出るNext.jsの丸いアイコンは開発中だけの表示で、本番では出ない。

| **ESLint** | コードの書き方の問題を自動でチェックしてくれるツール |
| **npm** | Node.jsに付いてくる、ライブラリを入れたり管理したりするツール(パッケージマネージャー) |
| **npx** | ライブラリを入れずに、コマンドを一時的に実行するための道具。`create-next-app` の実行に使った |
| **パッケージ / ライブラリ** | 他の人が作った、使い回せるプログラムの部品 |
| **node_modules** | 入れたパッケージの実体が置かれるフォルダ。大量のファイルがあるため、Gitには入れない |
| **開発サーバー** | 開発中にアプリを動かして確認するための、自分のPC上で動く仮のサーバー。`npm run dev` で起動する |

| **脆弱性** | セキュリティ上の弱点。`npm audit` は、入れたパッケージに既知の弱点がないかを調べるコマンド |
| **.gitignore** | Gitの管理から外すファイルを指定する設定ファイル |

| **フォーカス** | 入力欄にカーソルが入り、入力できる状態になっていること。目印として枠線を出す(フォーカスリング) |
| **コントラスト** | 文字と背景の明るさの差。差が小さいと読みにくいため、色の組み合わせを選ぶ基準になる |
| **`"use client"`** | ファイルの先頭に書く宣言。この部品を、ブラウザ側で動く部品(クライアントコンポーネント)にする |

| **`name` 属性** | 入力欄の項目名。フォームを送信するとき、この名前と入力値がセットで送られる |
| **`noValidate`** | フォームのブラウザ標準チェックを止める属性。自前のチェックに任せるときに使う |
| **`preventDefault`** | イベントの標準動作を止める処理。フォーム送信では、ページの再読み込みを止める |
